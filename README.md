# FISHRAND 🐟

An intentionally ridiculous physical entropy infrastructure built around a
fish, made with [archSLAYER44](https://github.com/archSLAYER44). A camera
watches a fish, our vision engine extracts movement
([`vision.py`](https://github.com/abijit2626/MeenCrypt) → `fish_log.json`),
and [**MeenCrypt**](https://github.com/abijit2626/MeenCrypt) turns that
movement into a genuinely careful cryptographic pipeline.

**TinkerHub Makeathon — theme: Useless Projects.**

> The joke: your diary is guarded by a goldfish.
> The truth (and the honest demo pitch): the fish contributes nothing
> cryptographically — the **OS CSPRNG + HKDF + AES-256-GCM** do all the real
> security work. FISHRAND demonstrates *why* mixing a weak physical input
> with a trusted CSPRNG is a sound design, rather than claiming magic.

The current punchline is a **universal USB code**: create `code.txt` once
(a `secrets.token_hex(32)`, generated by the OS CSPRNG), and that one code
can unlock **any** message the fish encrypts. Every package binds its own
fish window: in **v3 the fish drives the key schedule** (a per-window
HMAC-SHA256 chain) and the package carries a public **fish commitment** that
verifies "this exact fish built this ciphertext". The secret, key, and fish
data are never stored inside the package.

### Package versions

All three versions remain fully decryptable. v3 is the current default for
every encrypt-with-code path (the CLI and the diary website).

| Version | Key derivation | Secret | Public commitment | Status |
|---|---|---|---|---|
| **v1** | `HKDF-SHA256(os_random ‖ fish_digest)` | `os_random` **embedded in the package** | No | Legacy self-contained demo (`--demo` / no code) |
| **v2** | `HKDF-SHA256(USB code ‖ fish_digest)` | USB code (`code.txt`), **not stored** | No | Legacy — no longer produced, always decryptable |
| **v3** | HMAC-SHA256 per-unit chain → `HKDF(commitment ‖ chain ‖ fish_noise)` | USB code (`code.txt`), **not stored** | **Yes** — `fish_commitment_b64` | **Current default** |

The full story of how each version came to be lives in
[`documentary/how-it-was-built.md`](documentary/how-it-was-built.md).

## Pipeline

```
              Fish vision window  (friend's vision.py → NDJSON fish_log.json)
                                │
V  1  Input contract   validate_observations()      v1 samples OR v2 frames;
                                │                     strict schema, no NaN/Inf
V  2  Canonicalization canonicalize_observations()  same data ⇒ same bytes
                                │
V  3  Conditioning     SHA-256(canonical) → fish_digest  (compression, NOT entropy)
                                │                        │
                                └──────────────┬─────────┘
                                               ▼
V  4  Secret            universal USB code.txt            ← the ONLY secret,
                               │                          ← created by the OS CSPRNG
                               ▼
V  5  Fish-chain key    HMAC-SHA256 per unit (frames/samples):
      schedule          state₀ = HMAC(code,"FISHRAND-v3‖\x01")
                        stateᵢ = HMAC(code, stateᵢ₋₁ ‖ unit ‖ i)
                        commitment = HMAC(code,"FISHRAND-v3‖\x02‖state)
                        key = HKDF-SHA256(commitment ‖ state ‖ fish_noise,
                                          info="…-v3-fishchain")  → 32 bytes
                        fish_noise  → packed floats: timestamps, activity,
                                       centroid, area, speed, direction
                                │
                                ▼
V  6  AES-256-GCM     encrypt(key, fresh 12-byte nonce, plaintext, canonical AAD)
                                │
                                ▼
V  7  Package          JSON: ciphertext ‖ tag, nonce, AAD, metadata,
                       fish_hash, fish_commitment (public)
                       v1  → os_random embedded (legacy self-contained demo)
                       v2  → NO secret stored; key = HKDF(code ‖ fish_digest)
                       v3  → NO secret stored; key = fish-chain (current default)
                                │
                              save / USB
                                ▼
V  8  Decrypt          re-run chain → verify commitment → GCM tag verify
                       → plaintext OR reject
```

## The universal USB code

```bash
# step 0 — generate the code once on your USB stick
.venv/bin/python cli.py init --dir /media/USB     # writes /media/USB/code.txt

# step 1 — encrypt a diary (fish collected automatically, code read from USB)
.venv/bin/python cli.py encrypt --diary examples/diary.txt --usb /media/USB \
    --out /media/USB/diary.pkg

# step 2 — on another laptop, unlock with the same stick
.venv/bin/python cli.py decrypt --pkg /media/USB/diary.pkg --usb /media/USB
```

The code is resolved from (in order) `--code <file>`, `--usb <dir>/code.txt`,
`FISHRAND_USB_CODE`, or `./code.txt`. A `--demo` flag produces the legacy
v1 self-contained package (secret embedded) when you don't want the USB.

The diary website does the same thing without a terminal: paste/load
`code.txt`, encrypt, and the browser downloads `diary-<timestamp>.pkg`.
On another machine, load that `.pkg` + the same code → the diary decrypts.
Wrong or missing code ⇒ `AUTHENTICATION FAILED` (GCM tag refuses).

**Why "one code unlocks anything"?** Each package binds its own fish window
(per-frame units + noise in the v3 fish-chain, `metadata.fish_observations`).
So the code is the key holder and the fish does the key-schedule + binding —
the code alone unlocks every message the fish ever encrypts.

## Fish observations: collected automatically on encrypt

The dashboard and CLI collect the current window the instant you encrypt,
and bind it into the package so decrypt always uses the *same* fish
(decrypting a package with different fish data fails authentication).

Source order (first contract-valid source wins):

| Order | Source | Env var |
|---|---|---|
| 1 | Vision engine's NDJSON `fish_log.json` (inbox) | `FISHRAND_FISH_INBOX=1`, `FISHRAND_FISH_INBOX_DIR=...` |
| 2 | Teammate's CV service (HTTP) | `FISHRAND_FISH_URL=...` |
| 3 | Bundled vision sample (default) | `FISHRAND_FISH_FALLBACK=.../sample_vision_data.json` |

Extra knobs:

| Env var | Default | Meaning |
|---|---|---|
| `FISHRAND_VISION_FRAMES` | `60` | how many latest frames to bundle per window (inbox mode) |
| `FISHRAND_USB_CODE` | – | path to `code.txt` so the *server* attaches the code when absent |

### Merging your friend's vision engine

`vision.py` writes one JSON object every ~5 s to `fish_log.json`:

```json
{"timestamp": 1750000000.0, "fish_count": 1, "activity_pct": 4.2,
 "fish": [{"id": 0, "centroid": [120.5, 240.2], "area": 320.5,
           "speed": 3.2, "direction_rad": 0.2}]}
```

It's an **NDJSON log** (one object per line). Pointing the inbox at it is a
zero-code integration:

```bash
FISHRAND_FISH_INBOX=1 FISHRAND_FISH_INBOX_DIR=/path/to/logs \
  .venv/bin/uvicorn server.main:app --port 8000
```

The collector windows the latest `FISHRAND_VISION_FRAMES` frames into a
single v2 contract and re-emits. Their code can also `POST
/api/observations` (`examples/fish_sender.py`) and the dashboard feed
updates live over SSE.

### Vision contract (v2)

```json
{"schema_version": 2, "source": "fish_vision",
 "frames": [{"timestamp": <float sec>, "fish_count": <int>, "activity_pct": 0-100,
             "fish": [{"id": <int>, "centroid": [x, y], "area": <float>,
                       "speed": <float>, "direction_rad": -π..π}]}]}
```

Legacy v1 (`samples`) remains fully supported and decryptable.

## API surface

```python
from fishrand import (
    encrypt_with_fish_entropy,   # (fish_json, plaintext, session_code=None) -> package
    decrypt_package,             # (fish_json, package, session_code=None) -> bytes
    derive_key,                  # low-level HKDF
    encrypt_message, decrypt_message,
    load_observations, validate_observations, canonicalize_observations,
)
```

HTTP: `POST /api/encrypt {plaintext, code?}` and `POST /api/decrypt
{package, code?}` — both SSE, ending in a `done` frame
(`encrypted`/`decrypted`/`rejected`).

## Security model & honest wording

- Fish-derived values are **NOT cryptographically secure randomness**.
- The SHA-256 `fish_digest` is *conditioning*: it compresses the observation
  stream to fixed size. It does **not** create entropy.
- The **universal USB code is the ONLY secret** — it is generated once by the
  OS CSPRNG (`secrets.token_hex(32)` in `init`). No `random.*`, no time seeds,
  no hand-rolled PRNG.
- **v3 fish-chain** (current): the fish drives a per-unit HMAC-SHA256 key
  schedule and signs the window with a keyed **commitment**. The commitment is
  public in the package; decrypting with different fish (or a different code)
  makes the commitment mismatch and the GCM tag refuse. Fish data is incidental
  — `state₀ = HMAC(code,…)` means the code is still what makes keys secret.
- Mixing uses **standard HKDF-SHA256** with explicit domain-separation
  `info` per version (`FISHRAND-AES256-GCM-v1` / `…-v2-usbcode` /
  `…-v3-fishchain`).
- AES-256-GCM from the audited `cryptography` library. Fresh nonce per
  session; every decryption verifies the **GCM authentication tag**; tampered
  data is rejected, never returned.
- The code is read from the USB/`FISHRAND_USB_CODE` at encrypt/decrypt time
  only — it is never stored in the package, the logs, or a callable.

### What's the demo tradeoff now?

- **v1 packages** (no code supplied, `--demo`) embed `os_random` so the old
  self-contained demo keeps working. It's documented as a demo simplification.
- **v2 packages** (legacy code flow) store **no secret**: key
  `= HKDF(code ‖ fish_digest)`. Fully decryptable, kept for compat.
- **v3 packages** (the current diary flow, USB code set) store **no secret**
  and *chain* the key through the fish: ciphertext without `code.txt` is
  opaque. This is the honest build.

## Canonical serialization rules

1. Fixed field ordering. v1: `schema_version, source, samples`,
   per sample `timestamp_ns, position, displacement, acceleration`,
   per vector `x, y`. v2: `schema_version, source, frames`, per frame
   `timestamp, fish_count, activity_pct, fish`, per fish
   `id, centroid, area, speed, direction_rad`.
2. Deterministic numbers: ints as-is (`1`), floats via `repr` (`1.0`, `3.14`).
   NaN/±inf rejected in validation.
3. UTF-8, zero unnecessary whitespace.
4. `schema_version` and `source` are embedded in the canonical stream.
   Changing these rules is a breaking change (bump version).
